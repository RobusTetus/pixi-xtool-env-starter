# pixi-xtool-env-starter

A self-contained [pixi](https://pixi.sh) environment for building iOS apps on Linux with
[xtool](https://github.com/xtool-org/xtool) and the official Swift toolchain. Nothing is
installed system-wide: the C/C++ toolchain and sysroot come from conda-forge, and Swift and
xtool are downloaded into `.pixi/tools/` (gitignored).

## Quick start

```bash
pixi run setup      # download + verify Swift, download xtool (one-time)
pixi shell          # enter the environment (swift, xtool, ld on PATH)
xtool setup         # one-time xtool setup: Apple ID login + Xcode.xip for the iOS SDK
xtool new recipes   # create the app project in ./recipes (if it doesn't exist yet)

pixi run build      # = xtool dev build   (in ./recipes)
pixi run dev        # = xtool dev         (build + install/run on a connected device)
```

## How it works

- `pixi.toml` pulls `gcc`, `g++`, `binutils` and a glibc 2.34 sysroot from conda-forge.
- `scripts/setup.sh` downloads the Swift toolchain (GPG-verified against swift.org keys)
  and extracts the xtool AppImage (no FUSE needed).
- `scripts/activate.sh` runs on every `pixi shell` / `pixi run` and wires everything
  together with symlinks: GCC runtime files, an unprefixed `ld`, `libstdc++`/`libgcc_s`,
  and the Swift runtime inside the sysroot. It also writes a clang config file so the
  toolchain's clang always uses the conda sysroot for Linux targets.

## Limitations

- **x86_64 Linux only.** `platforms = ['linux-64']` and the activation script hardcode the
  `x86_64-conda-linux-gnu` / `x86_64-unknown-linux-gnu` triples. aarch64 Linux would need
  changes in both files; macOS/Windows are not supported.
- **xtool is not pinned by default.** `XTOOL_VERSION="latest"` means two machines may get
  different xtool builds. Once installed, `latest` is not re-downloaded unless forced.
- **Paths are absolute.** The generated `.pixi/tools/bin/xtool` wrapper and the clang
  `.cfg` contain absolute paths. If you move or rename the project directory, run
  `pixi shell` (fixes the `.cfg`) and `FORCE_XTOOL=1 pixi run setup` (fixes the wrapper).
- **The Swift toolchain is modified in place.** `activate.sh` writes
  `x86_64-unknown-linux-gnu.cfg` next to the toolchain's clang. Don't point this setup at a
  shared Swift installation.
- **`pixi clean` wipes the downloads.** Swift and xtool live in `.pixi/tools/`, so after a
  clean you need to run `pixi run setup` again (Swift is ~1 GB).
- **Apple requirements still apply.** You need an Apple ID and an `Xcode.xip` for
  `xtool setup`, and the usual free-account signing limits (7-day provisioning, limited
  number of apps) apply.
- **Network access is required** for `setup` (swift.org, github.com) — there is no offline
  mode or mirror support.
- **Tasks assume the app lives in `./recipes`.** `build` and `dev` fail until that
  directory exists.

## Customizing

| What | Where | How |
|---|---|---|
| Swift version | `scripts/setup.sh` | Change `SWIFT_VERSION`, then `pixi run setup`. Re-downloads automatically when the version differs. |
| Swift build flavor | `scripts/setup.sh` | Change `SWIFT_PLATFORM` (e.g. `ubuntu24.04`, `fedora39`, `amazonlinux2`) to match a build listed on [swift.org/install](https://www.swift.org/install/linux/). `ubi9` works well on Fedora/RHEL. |
| xtool version | `scripts/setup.sh` | Set `XTOOL_VERSION` to a release tag (e.g. `1.2.0`) for reproducible installs. |
| Update xtool (when `latest`) | shell | `FORCE_XTOOL=1 pixi run setup` |
| App directory | `pixi.toml` | Change `cwd = "recipes"` in the `build` and `dev` tasks. |
| Extra tasks | `pixi.toml` | Add entries under `[tasks]`, e.g. `test = { cmd = "swift test", cwd = "recipes" }`. |
| Extra tools | `pixi.toml` | `pixi add <package>` for anything on conda-forge (e.g. `pixi add jq`). |
| glibc baseline | `pixi.toml` | Adjust `sysroot_linux-64`. It must be at least what the chosen Swift build needs (2.34 for `ubi9`). |

## Committing

Commit `pixi.toml`, `pixi.lock` (generated by `pixi install`), `scripts/`, and your app
sources. `.pixi/` is ignored, so the toolchain is always recreated from the pinned versions.
